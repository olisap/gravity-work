🚨 Section 4 — Priority Blockers (Must Fix Before Go-Live)

🚨
The following 4 items will break user-facing functionality or make the abandonment recovery system ineffective even though the backend sends correctly.
🔴 Blocker 1 — Resume Checkout Token Not Handled

The abandonment email sends a link like https://app.olistores.com.ng/checkout?resume=RESUME-1725641234567. But when the customer clicks that link, the CheckoutPage.jsx reads the ?resume= param but makes no API call to load the saved draft data. The form loads blank instead of pre-filled with their name, phone, address and cart items.

Fix needed: Add endpoint GET /api/orders/resume/:token that returns the draft by resume token. In CheckoutPage, call this on mount and pre-fill the form state.

Impact if not fixed: Recovery emails go out but customers arrive at a blank form — abandonment recovery fails completely.

🔴 Blocker 2 — Expenses Data Not Persisted

The ExpensesAccounting.jsx stores expenses in useState. Every page refresh or login clears all expense records. The Profit = Revenue – Expenses calculation is therefore unreliable and cannot be trusted for business decisions.

Fix needed: Create Supabase expenses table, /api/expenses CRUD routes, and wire up the React component to fetch/post real data.

🟡 Blocker 3 — Marketing Broadcast is Cosmetic Only

The MarketingHub shows a professional broadcast UI. Staff may use it believing messages are actually being sent. The handleSendBroadcast() function only updates local state with a fake log entry. No real message is dispatched to any customer.

Fix needed: Backend broadcast endpoint with audience query, and real Brevo / Termii bulk send. Add a clear "DEMO MODE" label until the real API is wired.

🟡 Blocker 4 — No Real-time Order Sync

If multiple staff are logged in simultaneously (confirmation staff + logistics), order status changes made by one user are not reflected for others without a manual refresh. In high-volume operations, this leads to double-confirmation calls and conflicting status updates.

Fix needed: Enable Supabase real-time subscription on the orders table in App.jsx, scoped to store_id. Update orders state on INSERT/UPDATE events.
